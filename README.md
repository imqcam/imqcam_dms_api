# imqcam_dms_api

Notebooks for pulling IMQCAM DMS data into pandas and analysing it. The DMS is a [Girder](https://girder.readthedocs.io/) instance at `https://data.imqcam.org/api/v1`.

Data lives there in two shapes. **Forms and form entries** are the curated structured records — every experimental record belongs to one of nine *forms*, and these notebooks cover all of them. **Raw and derived data files** are the measurement files themselves, Girder items tagged with a `data_type` and an `igsn`, reached through the `/imqcam` endpoints. The two are joined only by IGSN; the analysis notebooks work on the entry side.

- **`tutorials/`** — Learning notebooks for the DMS REST API
  - `01_api_endpoints.ipynb` — Raw coverage of `/form` and `/entry`, then the `/imqcam` file endpoints
  - `02_form_catalog.ipynb` — Every form, with field-level profiles and fill rates
  - `03_sample_tracking.ipynb` — `/sample` and its event history, with the custody timeline
  - `04_file_collections.ipynb` — Find and download raw or derived items by data type, IGSN, composition, and item-name extension
  - `05_igsn_forms.ipynb` — Export a selected IMQCAM form and one or more IGSNs to an Excel workbook in `downloads/`
  - **`analysis/`** — One notebook per form family
    - `01_build_parameters.ipynb` — Laser process parameters unified across four forms, with a unit fix validated against energy density
    - `02_flexural_fatigue.ipynb` — Four-point flexural fatigue, S–N curves and run-out handling
    - `03_fractography.ipynb` — Defect size, shape and position on fracture surfaces
    - `04_powder_and_heat_treatment.ipynb` — Feedstock chemistry, particle sizing and heat-treatment schedules
    - `06_linked_dataset.ipynb` — The process–property–defect join across forms
- **`imqcam.py`** — Shared helpers: authentication, paginated fetching, and flattening nested payloads
- **`results/`** — contains all_infill.csv regenerated by `analysis/01_build_parameters.ipynb` and PNGs of sample tracking artefacts. 

## Installation

Install Python dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```
GIRDER_API_KEY=your_api_key_here
```

`get_client()` defaults to `https://data.imqcam.org/api/v1`. It reads the `.env` file in preference to ambient environment variables, because `GIRDER_API_URL` left over from a neighbouring Girder deployment (`data.htmdec.org` runs the same API) otherwise redirects every request to a host where this key is invalid. Set `GIRDER_API_URL` in `.env` to point somewhere else deliberately.

Start Jupyter and open any notebook:

```bash
jupyter notebook
```

## What the data looks like

758 entries and 696 registered IGSNs, spread very unevenly across nine forms:

| Form | Entries | Holds |
|---|---|---|
| NASA Ti64 30um Layers Data | 201 | Process parameters plus yield strength, elongation, modulus, porosity |
| Four-point flexural test | 193 | Fatigue tests, nested as a list per specimen |
| Archival ULI Build (simplified) | 192 | Laser power, velocity and hatch spacing |
| Fractography Record | 72 | Defect morphology, nested as a list per specimen |
| Micromechanical Simulation Data | 46 | Crystal-plasticity simulation configuration and file pointers |
| AM Build Parameters | 27 | Parameter sets per scan type |
| Raw Powder Details | 11 | Feedstock chemistry and particle sizing |
| Sample Heat Treatment Record | 9 | Stress relief and subsequent steps |
| Printer Build | 7 | The richest schema: four scan types, geometries, powder linkage |

A further 52 entries carry `formId`s that `/form` no longer returns — retired versions of the simulation form. `tutorials/02_form_catalog.ipynb` reports them rather than dropping them.

## File collections for modelers

`tutorials/04_file_collections.ipynb` demonstrates the workflow a modeler can use instead of browsing the DMS manually:

1. List registered measurement types such as `ebsd_raw`, `ebsd_derived`, `ct_tomography`, and `fractography_raw`.
2. Query one or more exact IGSNs, such as `CMXMAG00001-039`. The workflow does not expand a parent build IGSN into its child part IGSNs.
3. Query `/imqcam/datafiles` by optional `data_type` and IGSN.
4. Request additional item metadata, such as `meta.composition`, with the `extraFields` parameter.
5. Load the returned items into a pandas `DataFrame` for filtering, grouping, and inspection.
6. Download selected items into a structured local directory organized by the search filters captured with the results.

An extension filter checks the returned **item name** only; it does not inspect a folder item's contents. When an item matches, the complete item is downloaded.

The notebook also explains why `/imqcam/count` and `/imqcam/datafiles` can report different totals: the former counts classified storage files, while the latter returns queryable Girder items with the metadata needed to identify their specimen. Counts should therefore be treated as different measurements, not as interchangeable row counts.
